CASE STUDY · 2025 — 운영 중

전기기사닷컴

기출문항을 구조화하고 오답 이력을 기반으로 다음 문제를 고르는 전기기사 필기 학습 플랫폼입니다. 기획과 개발, 운영을 직접 맡고 있습니다.

ROLE
기획 · 프론트엔드 · 백엔드 · 인프라
STACK
React · FastAPI · PostgreSQL · Neo4j
PERIOD
2025.03 — 운영 중

OVERVIEW

전기기사 필기는 과목이 다섯 개이고 기출 범위가 넓습니다. 수험생 대부분은 문제를 많이 푸는 것으로 대응하지만, 어떤 개념에서 반복해 틀리는지는 스스로 파악하기 어렵습니다. 이 플랫폼은 그 부분을 데이터로 대신 잡아주는 것을 목표로 만들었습니다.

PROBLEM

  • 기출 PDF가 2단 조판이라 텍스트 추출 시 문항과 보기가 뒤섞임
  • 회로도와 수식이 이미지로만 존재해 검색과 분류가 불가능
  • 문항이 어떤 개념에 속하는지 표시가 없어 취약점 분석이 안 됨

APPROACH

PDF에서 문항을 뽑아 데이터베이스에 넣기까지를 다섯 단계로 나눴습니다. 각 단계는 독립 실행이 가능해, 특정 단계만 다시 돌릴 수 있습니다.

MY ROLE

  • 파이프라인 다섯 단계 전부 설계와 구현
  • 문항과 개념을 그래프로 연결하는 스키마 설계
  • 프론트엔드 학습 화면과 채점 API 구현
  • 배포와 장애 대응을 포함한 운영

ARCHITECTURE

RESULT

  • 기출 5개년 문항을 구조화된 데이터로 적재
  • 문항 추출 단계 수작업 검수 비율이 초기 대비 크게 감소
  • 오답 이력 기반 추천으로 재응시 정답률 개선 확인

다만 회로도가 포함된 문항은 아직 자동 처리 정확도가 낮아, 해당 유형만 별도 검수 단계를 두고 있습니다.

WHAT I LEARNED

파이프라인을 한 덩어리로 짜면 중간에서 실패했을 때 처음부터 다시 돌려야 합니다. 단계를 나누고 각 단계의 출력을 파일로 남기도록 바꾼 뒤에야 실제로 운영이 가능해졌습니다. 기능을 먼저 만들고 운영을 나중에 생각하면 늦다는 것을 이 프로젝트에서 배웠습니다.
